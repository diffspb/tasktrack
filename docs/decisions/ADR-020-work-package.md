# ADR-020: Задание (WorkPackage) — черновик на задаче и неизменяемые версии

**Статус:** Принято — решение принято при автономной реализации FR-003 (TT-09), подлежит ревью владельцем продукта  
**Дата:** 2026-09-30

## Контекст

[FR-003](../feature-requests/FR-003-portfolio-execution.md), TT-09: «обязательные поля готового задания и его неизменяемая версия WorkPackage: цель, результат, критерии, входы, ограничения и специализация. Неполное задание остаётся черновиком. Оригинал принятого пакета — в TaskTrack; YAML/JSON для консоли — закреплённая копия с ID, версией и digest». Консольный агент должен работать по точному тексту, а проверяющий — проверять результат по тем же критериям.

Варианты: хранить задание в `Task.description` / `Task.meta`; отдельная таблица версий; только редактируемое задание без версий.

## Решение

- **Черновик** — `Task.work_package_draft` (JSONB): цель, ожидаемый результат, критерии `{key?, text, required}`, входы `{kind, ref, version?, note?}`, ограничения, специализация. Редактирует автор задачи или менеджер; проверяется только форма полей.
- **Выпуск** (`POST /tasks/{id}/work-package/issue`) проверяет полноту: цель, результат, специализация и хотя бы один критерий. Неполное — `422 WORK_PACKAGE_INCOMPLETE` со списком недостающего, задание остаётся черновиком. Критериям без ключа присваиваются стабильные ключи `c1`, `c2`… — на них ссылаются предложение результата и проверка.
- **Версия** (`WorkPackage`: `task_id`, `version`, `content`, `digest`, `issued_by`) неизменна. `digest` — SHA-256 канонического JSON содержимого. `Task.work_package_version` указывает текущую. Выпуск без изменений — `409 WORK_PACKAGE_UNCHANGED`.
- **Экспорт** `GET /work-packages/{id}/export?format=json|yaml` — закреплённая копия: id, версия, digest, проект, задача, содержимое.
- Выпуск пишется в журнал (`work_package`, `issued`), правка черновика — тоже.

## Последствия

- Предложение результата и сессия исполнения ссылаются на конкретную версию задания; проверка берёт обязательные критерии из неё (ADR-021, ADR-022).
- Изменение черновика после выпуска видно («draft_changed» в карточке, причина ожидания в представлении руководителя) — работа по старой версии не выглядит актуальной без перевыпуска.
- «Принятые входы, допустимые версии, выделенный ресурс» (TT-11) и типизированные основания (TT-10) не входят: они зависят от контракта внешних систем. Входы пока хранятся как свободные ссылки.
