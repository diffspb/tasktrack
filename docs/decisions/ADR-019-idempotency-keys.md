# ADR-019: Безопасный повтор команд по `Idempotency-Key`

**Статус:** Принято — решение принято при автономной реализации FR-003 (TT-04), подлежит ревью владельцем продукта  
**Дата:** 2026-09-29

## Контекст

[FR-003](../feature-requests/FR-003-portfolio-execution.md), TT-04: «Безопасный повтор команд по идентификатору и хешу запроса. После потерянного ответа повтор возвращает прежний результат. Другой запрос с тем же ключом отклонён. Право доступа проверяется и при повторе». Нужно до автоматической связки служб: агент, потерявший ответ на `POST /tasks`, повторяет его и создаёт дубль.

Сложность — атомарность. Если запоминать ключ отдельно от команды, возможны два сбоя: ключ записан, а команда нет (повтор ничего не сделает), или команда выполнена, а ключ не записан (повтор выполнит её снова). Сервисы коммитят сами, а ответ формируется после коммита.

## Решение

- Клиент передаёт заголовок `Idempotency-Key` (1–255 символов `[A-Za-z0-9-_.:]`) в `POST`/`PUT`/`PATCH`/`DELETE`. Без заголовка поведение прежнее. Ключ действует в пределах пользователя (учётной записи, в т. ч. служебной) 24 часа.
- **Резерв в транзакции команды.** Зависимость роутера до вызова эндпоинта вставляет строку `idempotency_keys (user_id, key, request_hash)` через `INSERT … ON CONFLICT DO NOTHING` в сессию запроса. Коммит сервиса фиксирует резерв вместе с изменением; если команда падает, резерв удаляется (и в любом случае откатывается) — повтор выполнит её заново, что безопасно, ведь изменений не было.
- **Одновременный дубль** ждёт на первичном ключе, пока первый запрос не завершится, затем находит его строку и ждёт (до 5 с) сохранённого ответа.
- **Ответ** сохраняет ASGI-middleware сразу после успешного (2xx) ответа — отдельным коммитом. Повтор с тем же `request_hash` (метод, путь с query, тело) получает сохранённые статус и тело с заголовком `Idempotent-Replayed: true`.
- **Другой запрос с тем же ключом** — `422 IDEMPOTENCY_KEY_REUSED`.
- **Право при повторе.** При сохранении ответа в строку записываются проекты, которые изменила команда, — по событиям аудита той же транзакции (общий `xid`, [ADR-018](./ADR-018-audit-log-event-journal.md)). Повтор требует права записи (`member`+) в каждый из них, для системных событий — суперпользователя. Иначе обычная ошибка доступа, сохранённый ответ не выдаётся.
- **Потерянный ответ.** Если процесс упал между коммитом команды и сохранением ответа, строка остаётся без ответа. Повтор старше 60 с получает `409 IDEMPOTENCY_OUTCOME_UNKNOWN`: команда выполнена, клиент должен перечитать ресурс, а не повторять.

## Последствия

- Команда никогда не выполняется дважды при повторе с тем же ключом; окно «выполнено, ответ неизвестен» узкое и явно сообщается клиенту.
- Команды, которые не пишут событий аудита (воркфлоу, Гант, представления), воспроизводятся без повторной проверки прав на проект — только после аутентификации того же пользователя. Сужается по мере разметки журнала (`tech-debt.md`).
- MCP-инструменты ключ не принимают — повтор через MCP пока небезопасен (`tech-debt.md`, связано с FR-002 / TT-18).
- Строки старше 24 часов перезаписываются при повторном использовании ключа, но фоновой очистки нет; таблица растёт с числом команд с ключом.
